# Rust SDK 开发指南

适用：采用 [MIT 许可](../LICENSE)的 `tansr-sdk 0.1.0` 与 `tansr-sdk-demo 0.1.0`。本文包含 registry 固定版安装、新工程 quickstart 与源码开发用法；带 `-p tansr-sdk-demo` 的命令只用于完整源码工作区。对应英文：[Developer guide](guide.md) · [0.1.0 API 文档](https://docs.rs/tansr-sdk/0.1.0/tansr_sdk/)。

SDK crate 附带两份 README 和中英文使用指南。完整可运行示例属于独立 `tansr-sdk-demo` 包；下文 `demo/` 开头的路径均相对完整源码工作区。Demo 的 README 和示例源码随 Demo 包提供，不混入 SDK crate。

## 1. 接入与职责

SDK 是 Rust 2024 异步库，需要 Rust 1.85 或更新版本；源码开发使用项目固定工具链。Windows 构建需要 MSVC C/C++ 构建工具及 NASM，以满足当前 TLS provider 的构建依赖。运行 Cargo 的当前 shell 必须能找到这些工具，可先用 `nasm -v` 检查 NASM。以仓内 `rust-toolchain.toml`、`Cargo.lock` 和实际平台日志为准，不将 edition 最低版本当作完整传递依赖图已验证的 MSRV。

先检查 `cargo --version`、`rustc --version`。新工程不会继承本仓固定的 1.95.0 工具链；可在工程根放置 `rust-toolchain.toml`，内容为 `[toolchain]` 和下一行 `channel = "1.95.0"`。Windows 若仍命中旧的独立 Cargo 可执行文件，项目文件不能替它切换版本；用 `rustup toolchain install 1.95.0 --profile minimal` 安装，再以 `rustup run 1.95.0 cargo ...` 执行，无需修改全局默认。下方新工程步骤显式选用此工具链。

从 crates.io 添加固定版本：

```sh
cargo add tansr-sdk@=0.1.0
```

业务工程依赖：

```toml
[dependencies]
tansr-sdk = "=0.1.0"
tokio = { version = "1", features = ["macros", "rt-multi-thread", "signal", "time"] }
futures-util = "0.3"
```

本地开发 SDK 可用 `tansr-sdk = { path = "../tansr-rust" }`，但不能在发行验收中保留 `path`、`git` 或 `[patch]` 冒充公开消费。SDK 不嵌入 Serve；开发者自行部署 Serve，并通过登录服务向终端签发短期用户 token。

同版 Demo 单独安装：

```sh
cargo install tansr-sdk-demo --version 0.1.0 --locked
tansr-chat --help
tansr-tools --help
tansr-archive --help
```

安装后的命令参数与本文源码命令相同：把 `cargo run -p tansr-sdk-demo --bin NAME --` 替换为 `NAME` 即可。`quickstart` 是随 Demo 包分发的源码示例，不是安装后的二进制命令。

| 模块 | 责任 |
|---|---|
| `api` | 81 操作通用调用、发现/围栏、认证、三请求头、HTTP/SSE 与统一错误 |
| `session` | 创建/附着/恢复、多轮事件、审批问答、同轮输入、历史/快照/压缩和语音请求 |
| `executor` | 显式业务 handler、执行绑定、日志和租约；协商后按逐操作资格传输业务输出 |
| `archive` | 验证档案、加密存储、耐久 ACK、显式恢复与材料回供 |
| `canonical` / `sse` | 冻结编码、摘要及流语义；通常由高层模块使用 |

核心上下文编排、记忆选材、权限裁决、模型循环和用量属于 Serve/kernel。SDK 中“本地档案”不等于“全面本地记忆编排”。平台系统提示词与会话配置也沿既有 Serve 合同生效，终端不另建冲突的提示词层。

## 2. Serve、认证与网络

Serve 源地址只填写 scheme/host/port，例如 `https://serve.example.com`，不带 `/api`、查询或用户密码。正式远程服务使用 HTTPS；反向代理应保留统一响应头并允许 SSE 持续输出。客户端拒绝重定向和不受信证书，不用关闭 TLS 校验解决环境问题。

兼容性以 Serve 的实时发现与当前授权为准，不能只凭版本号或 `/api` 可访问判断：

| 功能 | Serve 必须提供 |
|---|---|
| 通用 API | 冻结 manifest r7 / 81 操作及匹配 schemaHash、统一响应头；SDK 验证合同围栏 |
| 会话 | `session.capabilities` 的 `sdk2-ext-v1` 发现声明所选 `sdk1` / `legacy-complete` 或 `sdk2-offload-v1` / `source-required` 组合可用；具体插入、语音等仍各查能力 |
| 业务工具 | 声明摘要匹配的 `tool.invoke`、执行器注册/初始化、首次设备与 workspace 绑定，以及当前 scope、授权与租约 |
| 业务输出 | `terminal-services-v1` 下 `execution-stream-v1` 协商通过，且普通 `tool.invoke` 原操作具有预算、输出窗和当前逐操作权限；仅支持 Shell/process 输出不够 |
| 档案与材料 | 宿主已供应 Source，`archive.capabilities` 和 binding 接受 `archive-transfer-v1`、`split-receipts-v1` ACK 格式及 `source-ack-with-durable-spool` 耐久模式；材料回供还需 `context-materials-v1` |

Serve/kernel 单独部署，其部署及登录入口由宿主提供，本包没有 Serve 启动命令。缺能力会明确失败，不自动换会话族、降低耐久级别或扩大权限。

示例仅使用 `TANSR_TOKEN_FILE`：三个命令在每次请求时重新读取最多 8 KiB 的单行 ASCII 短期 token；quickstart 只在启动时读取一次。文件不带 UTF-8 BOM，只允许当前用户读取，刷新后必须仍是同一应用、同一用户。不要把长期平台 appkey、模型密钥、token 值放进命令行、日志、Git 或包中。令牌续期不会更换已建立 SSE 的认证；换账号应停止旧流、执行器与存储访问，再新建客户端。

SDK 的 `ClientBuilder::token_provider` 可接宿主令牌管理器；它不自动登录，也不在 401 后盲目重放写操作。回调产生的 future 受请求取消约束，宿主应合并并发刷新。`token` 方法适合生命周期已受控的短期固定值；业务长连接优先 provider。

示例通用配置：

| 环境变量/选项 | 用途 |
|---|---|
| `TANSR_TOKEN_FILE` | 短期 token 私有文件，必填 |
| `TANSR_BASE_URL` / `--base` | Serve 源地址；选项优先，缺省 `http://127.0.0.1:8787` |
| `TANSR_SESSION_FAMILY` / `--family` | `sdk1` 或 `sdk2-offload-v1`，缺省 `sdk1` |
| `TANSR_APPLICATION_SCOPE_ID` | 工具示例的当前应用身份 |
| `TANSR_END_USER_ID` | 工具示例的当前终端用户 |
| `TANSR_AUTHORIZATION_REVISION` | 工具示例的当前授权代际 |
| `TANSR_ARCHIVE_KEY_FILE` | 私有文件路径；文件内容是 64 个十六进制字符表示的 32 字节档案密钥 |

后三个工具 scope 字段须来自已认证的宿主上下文，与 token/Serve 策略一致。客户端自行填写它们不会产生权限。档案密钥独立保管，丢失不能靠重新生成密钥打开原文件。

以下用于已安装的 Demo，先由宿主准备兼容 Serve 与私有令牌文件；替换源地址和文件路径，不把密钥值填进命令。PowerShell：

```powershell
$env:TANSR_BASE_URL = 'https://serve.example.com'
$env:TANSR_TOKEN_FILE = 'C:\private\tansr\token.txt'
$env:TANSR_SESSION_FAMILY = 'sdk1'
tansr-chat --message '请简短介绍你的能力'
```

Unix shell：

```sh
export TANSR_BASE_URL='https://serve.example.com'
export TANSR_TOKEN_FILE="$HOME/.config/tansr/token.txt"
export TANSR_SESSION_FAMILY='sdk1'
tansr-chat --message '请简短介绍你的能力'
```

档案的 `sync`、`recover`、`materials` 模式另设 `$env:TANSR_ARCHIVE_KEY_FILE = 'C:\private\tansr\archive-key.txt'`（PowerShell）或 `export TANSR_ARCHIVE_KEY_FILE="$HOME/.config/tansr/archive-key.txt"`（Unix）；仍只传已有私有文件的路径。journal、archive、intent 路径通过各自命令参数传入，不存在对应的自动配置环境变量。

## 3. 会话示例

完整最小程序为 [v0.1.0 quickstart](https://github.com/tansrai/tansr-rust/blob/v0.1.0/demo/examples/quickstart.rs)。新建业务工程并添加 registry 依赖：

```sh
rustup toolchain install 1.95.0 --profile minimal
rustup run 1.95.0 cargo new --bin --edition 2024 tansr-quickstart
cd tansr-quickstart
rustup run 1.95.0 cargo add 'tansr-sdk@=0.1.0'
rustup run 1.95.0 cargo add 'futures-util@0.3'
rustup run 1.95.0 cargo add 'tokio@1' --features 'macros,rt-multi-thread,signal,time'
```

将完整源码保存为 `src/main.rs`，沿用上一节的 `TANSR_BASE_URL`、`TANSR_TOKEN_FILE`。PowerShell：

```powershell
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/tansrai/tansr-rust/v0.1.0/demo/examples/quickstart.rs' -OutFile 'src/main.rs'
$env:TANSR_REQUEST_ID = 'quickstart-20261008-001'
rustup run 1.95.0 cargo run --locked
```

Unix shell：

```sh
curl --fail --location 'https://raw.githubusercontent.com/tansrai/tansr-rust/v0.1.0/demo/examples/quickstart.rs' -o src/main.rs
export TANSR_REQUEST_ID='quickstart-20261008-001'
rustup run 1.95.0 cargo run --locked
```

每次新的运行需设置并保留唯一 `TANSR_REQUEST_ID`，不要直接重复示例值：非空、最多 100 个 ASCII 字母、数字、`-` 或 `_`。程序派生 `-create` 和 `-send` 两个稳定请求键；写失回先对账，不能换新身份重跑。它固定使用 `sdk1` 和内置英文提问，不读取 `TANSR_SESSION_FAMILY`，不接受 chat 命令参数；遇审批、问题或工具请求明确失败。每次写截止 30 秒，总观察上限 300 秒。若源码保存为 `examples/quickstart.rs`，运行 `rustup run 1.95.0 cargo run --locked --example quickstart`。

完整源码工作区才使用 `cargo run --locked -p tansr-sdk-demo --example quickstart`；新业务工程不使用 `-p tansr-sdk-demo`。更完整的交互程序见 [chat.rs](https://github.com/tansrai/tansr-rust/blob/v0.1.0/demo/src/bin/chat.rs)，共享接线见 [lib.rs](https://github.com/tansrai/tansr-rust/blob/v0.1.0/demo/src/lib.rs)。安装后可直接运行：

```sh
tansr-chat --family sdk1 --message "请简短介绍你的能力"
tansr-chat --family sdk1 --resume SESSION_ID
```

Demo 创建时不带初始 prompt，先打开 SSE，再发送消息。`--resume` 只恢复原会话，失败不偷建替代会话。会话默认保留；Ctrl+C、超时和 `/quit` 只终止本地观察，不自动宣布 Serve 已取消，不隐式关闭会话。

`--message` 是非交互单轮模式；遇到审批或问题会显示票据并明确失败，随后可不带 `--message`、保持原 `--family` 恢复同一会话处理。交互模式不会自动批准。chat 默认总观察超时为 600 秒，`--timeout` 可设 1–86400 秒。

| 交互 | 语义 |
|---|---|
| 普通文本 | 空闲时发送新一轮；活动轮不自动截断 |
| `/interrupt` | 显式请求 Serve 中断；受理后仍等待终态 |
| `/allow TICKET` / `/deny TICKET` | 只回应当前 SSE 实际展示的审批票据，沿用原 digest；不自动同意 |
| `/answers TICKET JSON_ARRAY` | 回应当前问题，例如 `[{"questionId":"q1","selectedOptionIds":[],"freeText":"我的回答"}]` |
| `/insert JSON_OBJECT` | 向原活动轮插入内容，必须携带原 input ID、history epoch、turn ID；受理不代表模型已消费 |
| `/history` | `limit=0` 的计数查询，验证零值语义 |
| `/quit` | 停止本地观察；活动轮结果仍可能未知 |

插入示例的 ID 和代际应来自当前会话实际信息，不能直接复制占位符：

```json
{"inputId":"host-generated-stable-id","target":{"historyEpoch":"CURRENT_EPOCH","turnId":"CURRENT_TURN"},"content":{"text":"补充：优先处理第一项"},"ack":"durable"}
```

`durable` 能力关闭时明确失败，不退化为 memory。SDK 事件流及 chat 不自动重连；宿主显式重建观察，恢复 SSE 使用应用已处理水位，不拿“已解析/已投递”水位或档案 ACK、输出、材料水位代替。EOF、HTTP 202、旧轮完成、会话结束均不等于当前轮成功；新轮观察 `turn.started` 后匹配其终态。恢复已运行轮时，优先从实时 input capabilities 的 target 取得权威 turnId；不支持插入的自定义工厂可从完整有序事件重放重建当前轮身份，不要求启用插入能力。仅匹配当前身份及读取前水位之后的终态；读取期间已结束则重新读取会话状态，不会永远等待已过去的 started。重放有 gap 或仍不能确认活动轮身份时明确要求对账，不猜成功。

Sdk1 和 offload 都用统一 `/api`。Offload 的创建/材料 Source 还有独立生命周期；仅切换 family 不代表 Source 已供应。Snapshot/Checkpoint、Compact、Transcribe/Speak 通过 `Session` 公开方法接入；语音请求不包括录音/播放器或主模型原生音视频消息块。

chat/tools 首次创建 offload 会话额外要求 `--request-id STABLE_ID`；此参数不读取 quickstart 的 `TANSR_REQUEST_ID`。调用方保留这个身份，创建失回先查原请求，不生成替代会话。恢复已有会话不传此选项。

## 4. 显式工具与输出

完整接线：`demo/src/bin/tools.rs`。示例只安装只读合成订单工具 `DemoOrderStatus`，订单 `DEMO-001` 为假数据；不会安装任意 shell、读取本机文件或回退到 Serve 宿主执行。

```sh
cargo run -p tansr-sdk-demo --bin tansr-tools -- --journal ABSOLUTE_PRIVATE_DIRECTORY
```

工具示例先声明同一工具、注册执行器、初始化能力并绑定逻辑 workspace；确认 Serve 返回工具可用后才打印就绪。在第二终端执行 `tansr-chat --family 原会话族 --resume SESSION_ID`，使用 tools 打印的会话 ID，提问“查询订单 DEMO-001”。`--session` 复用的会话必须已声明同一工具与摘要。首次设备绑定与当前权限均须由兼容 Serve 实际支持。

默认不要求输出分块，业务 handler 仍可返回完整结果和耐久回执。明确要求远程输出时：

```sh
cargo run -p tansr-sdk-demo --bin tansr-tools -- --journal ABSOLUTE_PRIVATE_DIRECTORY --require-output
```

示例先调用 `Client::negotiate_output`，将得到的 `TerminalOptions` 连同 `require_output: true` 传入 `RunnerOptions`。Runner 执行前检查当前操作的真实输出窗及 scope/绑定；检查通过才交付 `ToolContext.output`。旧 Serve 只允许 process/Shell 输出的实现仍会拒绝普通业务输出；不能因为 `execution-stream-v1` 协商 accepted 就跳过逐操作检查，也不能增加 Shell 权限或伪装工具类型绕过。部署条件见第 2 节能力表，缺条件时在 handler 执行前失败。

订单 handler 调用 `output.capture("stdout", ...)` 发送首块，经过 750ms 可取消的合成查询等待后发送 stderr 末块。capture 只把原字节放入有界异步队列；Runner 在 handler 返回后固定最终 seal 并等待 ACK。业务结果与输出确认分开：若业务返回确定结果但输出未确认，保留其耐久回执并对原输出对账，不能把它改成“业务没执行”或重跑函数。标准库的 `println!` 不会自动进入该输出窗，业务必须显式使用 context 中的 writer。

需要分别处理两种结果时，使用 `Runner::execute_with_output` 返回的 `ExecutionOutcome { receipt, output }`。简便的 `execute` 和循环 `run` 会以 `Error::OutputIncomplete` 明确报告输出待确认；其中 `run` 已先提交确定的业务回执。Demo 使用固定脱敏提示保留 journal、对原回执查询，不再次调用 handler。

底层 writer 保留 stdout/stderr 捕获顺序和原始字节，满队列截断连续前缀但继续排空生产端；不得借此打印未经过滤的凭据。Abort 只停输出上传，不证明工具已经取消。该 Demo 没有 process.exec/Shell/PTY 适配；真实业务输出测试也不等于真实 shell 验收。

| 结果 | 含义 |
|---|---|
| 合法 `status:ok` 或业务 `status:error` | 确定的业务返回，执行可形成 completed 回执 |
| `ToolError::Rejected` | 宿主能够证明尚未产生副作用 |
| `ToolError::Unknown`、panic、非法结果或不能证明的取消 | 未知结果；不能删除 journal 或重铸操作重新执行 |

执行前后当前登录/撤销/资源权限仍由宿主检查。Demo 的授权器只限定这条短时合成会话、scope、绑定和工具；生产宿主必须接入真实授权检查。`readOnly` 声明不替代订单归属检查。受限执行器票据不能运行控制者绑定步骤，应由独立控制者先协商并使用受限状态入口；不能失败后提权回退。

文件 journal 是私有执行记录，不是通用加密仓库。必须保存原状态用于崩溃和失回恢复。合作型 handler 应响应取消；SDK 无法安全强杀任意不合作宿主线程。输出队列首版没有跨进程无损续传承诺，重启后的未确认输出保留 unknown。

## 5. 本地档案与材料

存储职责分开：会话权威状态、上下文与记忆选材属于 Serve；`FileStore` 是本机单设备的加密档案与恢复状态；executor journal 是受文件权限保护的执行记录，本身不加密。SDK 不提供统一的“热/温/冷”记忆迁移、自动分层缓存、跨设备同步或备份保留策略，宿主需自行提供密钥管理及所需存储策略。

完整接线：`demo/src/bin/archive.rs`。`ArchiveClient` 读取 Source/binding/status；`FileStore` 保存身份、原始正文/附件、待决 ACK 与确认 coverage。只在原子耐久落盘后 ACK，不把解析完成或普通写返回当作可释放服务端档案的证据。

示例需要绝对私有路径、原绑定及密钥文件。首次绑定创建应先耐久保存完整 `BindingCreateRequest`（含原 requestId/operationEpoch/body），再发送；创建失回查询原操作，不换键新建。Source 存储/provider 的注册仍是 Serve 宿主配置，不虚构独立的 Source 注册端点。

```sh
cargo run -p tansr-sdk-demo --bin tansr-archive -- --mode prepare-create --session SESSION_ID --source SOURCE_ID --request-id STABLE_ID --intent ABSOLUTE_PRIVATE_INTENT
cargo run -p tansr-sdk-demo --bin tansr-archive -- --mode create --intent ABSOLUTE_PRIVATE_INTENT
cargo run -p tansr-sdk-demo --bin tansr-archive -- --mode creation-status --intent ABSOLUTE_PRIVATE_INTENT
```

prepare-create 只落盘，不发创建请求。创建响应未知时保留这个文件，查询原操作。同步与恢复继续用原绑定、原文件与原密钥。

```sh
cargo run -p tansr-sdk-demo --bin tansr-archive -- --binding BINDING_ID --file ABSOLUTE_PRIVATE_FILE --mode sync
cargo run -p tansr-sdk-demo --bin tansr-archive -- --binding BINDING_ID --file ABSOLUTE_PRIVATE_FILE --mode recover --request-id STABLE_RECOVERY_ID
```

普通 sync 会处理原待决 ACK，但不会悄悄新建 stale rebase 意图。`recover` 是显式恢复入口，只有明确 stale If-Match 才准备恢复映射；普通 412、busy、撤权、网络失回不触发。成功恢复一次 ACK 不表示全部档案同步完成，随后继续 sync。不得清除原 pending 来绕过错误。

`materials` 模式只回供 Serve 即时请求的已验证记录/附件，正文保持原始字节。收到请求时立即固定 `SystemTime` 截止时间，在后续 binding 查询和存储校验之后仍向 `prepare_materials_before` 传这个原截止；等待和重试不能重置 `remainingTtlMs`。若应用持久保存材料请求，也应保存原截止；旧便利方法 `prepare_materials` 仅用于刚收到的新鲜请求。最终响应先保存在 --intent，再提交；失回可按同一文件查询或明确重提。

```sh
cargo run -p tansr-sdk-demo --bin tansr-archive -- --mode materials --binding BINDING_ID --file ABSOLUTE_PRIVATE_FILE --request-id STABLE_RESPONSE_ID --intent NEW_PRIVATE_RESPONSE_FILE
cargo run -p tansr-sdk-demo --bin tansr-archive -- --mode material-status --intent NEW_PRIVATE_RESPONSE_FILE
```

`material-submit` 使用同一原响应，不能更换 requestId 或 operationEpoch。received 与 consumed 分开；202/received 不意味着上下文已经重建、档案可删除或模型已经看过内容。SDK 不上传全历史来掩盖材料链路缺口。

内置介质只承诺本 Rust 格式，不保证打开 Go/Node 文件。密文损坏、错密钥、容量不足、链接/reparse point 越界、并发写者或撤权均应失败并保留原档案。Unix 权限、Windows ACL、文件替换和目录同步需要各自原生验收；进程崩溃验证不是物理掉电 SLA。

## 6. 错误与资源关闭

`api::Error` 区分输入、合同、网络、服务器、取消、存储及 unknown。统一错误的 code/retryAction 与领域 detail 分开。不要打印 token、任意错误正文、业务参数或档案内容；Demo 对输出控制字符做显示层清理，不修改摘要承诺的原字节。

`ApiError` 的 `Display` 已脱敏；派生的 `Debug` 仍保留原 `message` 与 `detail`，仅供宿主在受控诊断流程中处理，不能直接写入用户日志。`Display` 的脱敏测试不代表 `Debug` 也已脱敏。

写操作保存同一键、正文、前置条件和 deadline。只有合同明示允许才重放同一请求；网络失回先查询原身份。不得换新键重试副作用或延长原 deadline。HTTP 层关闭隐藏重试。

`WriteOptions.deadline` 同时覆盖能力发现、closure 前置检查和最终写请求。Interrupt 响应失回时保留原会话，通过 metadata、可信 input target 及已处理水位之后的事件对账，用 `TurnTracker::resume` 跟踪原轮；不能偷建会话或假设存在未提供的通用请求查询 API。`input_status` 需原 input ID、HistoryEpoch、TurnID；轮结束后同 ID 同体仍可能返回原回执，新输入则被拒绝。Checkpoint restore 会改变历史代际，不能沿用旧 target。

完整 quickstart 与三个命令源码随 `--all-targets` 编译。示例共享库 `demo/src/lib.rs` 还提供 handler 输出与材料原截止处理的 `no_run` doctest；`cargo test --doc -p tansr-sdk-demo` 编译这些片段而不联系 Serve。文档可编译与真实 Demo 验收分别记录。

丢弃流/future 只取消本地资源，不向 Serve 伪造业务终态。应在正常退出路径显式关闭流、停止 Runner 并等待其返回、释放文件锁；持久 ACK 不在 Drop 中偷发。SDK 不建立全局 Tokio runtime。CLI 输入线程属于短生命示例进程，不属于 SDK 后台任务。
